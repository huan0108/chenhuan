# 零基础安装与上线

## 推荐方式：让 Codex 代操作

如果你使用 Codex、Cursor Agent、Claude Code 等能操作项目文件和终端的 AI，不需要自己逐条输入命令。

### “打开项目文件夹”到底打开哪一个？

这里不是打开某个文件。请先解压 ZIP，然后进入解压出来的文件夹，直到在同一个窗口里直接看到：

```text
使用说明-请先看.md
AGENTS.md
package.json
src
public
docs
```

同时包含这些内容的整个文件夹才是项目文件夹。不要只选择 `package.json`，不要选择 `src`，也不要选择它们外面多套的一层空文件夹。

### Codex 桌面应用怎样选择？

1. 打开 Codex 并登录。
2. 点击“Open folder”“Open local project”“Add project”或“打开文件夹”；不同版本名称可能不同。
3. 找到上面确认过的项目文件夹，只单击选中该文件夹。
4. 点击“选择文件夹”或“Select Folder”，不要双击进入 `src`。
5. 如果出现信任提示，确认压缩包来自卖家后选择信任。
6. 一个项目只添加这一个文件夹，不要再添加素材盘或第二个目录。

如果使用 Codex 命令行：先在 Windows 文件资源管理器中打开正确的项目文件夹，点击顶部地址栏，输入 `powershell` 并回车，再在新窗口输入 `codex`。

浏览器里的普通 Codex/聊天页面不能直接读取本地文件夹。零基础用户应使用 Codex 桌面应用或 Cursor；云端 Codex 需要先连接私有 GitHub 仓库。

### 创建对话后一次启动

在新建好的 Codex 项目对话中，只需发送下面这一整段：

```text
我是完全零基础用户。请读取根目录的 AGENTS.md，并连续完成网站的首次本地启动：
1. 先确认根目录同时存在 package.json、AGENTS.md、src 和 public；如果缺少任何一项就停止并告诉我选错了文件夹；
2. 检查 Node.js 是否不低于 20.19；如果电脑没有 Node.js 或必须安装系统软件，先征得我的确认；
3. Node.js 已符合要求时，我授权你安装当前项目依赖，然后运行模板检查并启动本地预览；
4. 正常步骤之间不要反复询问我。只有涉及管理员权限、删除或覆盖现有文件、登录、上传、创建仓库或发布时才暂停确认；
5. 启动成功后把完整的 Local 网址发给我，然后停止，不要修改网站内容。
```

Codex 会检查文件夹和环境、安装依赖、检查模板并启动网站。Node.js 已安装时，中间通常不需要继续回复；最后点击它给出的 `http://localhost:...` 地址。

网站打开后，不需要完成固定问卷。直接用自然语言告诉 Codex 想替换、增加、删除或调整什么即可；需要更精确控制时，再使用 [AI 提示词包](AI提示词包.md) 中的对应模板。上线时使用“让 Codex 协助上线”。

成功标志：Codex 告诉你检查通过，并给出一个 `http://localhost:...` 的本地网址。

AI 不能绕过系统权限、账号登录、验证码或付费确认。它需要安装 Node.js、创建仓库、上传源码或发布网站时，应先解释并等待你确认。

## 手动备用流程

只有 AI 无法操作、你想理解每一步，或客服要求手动排查时，才需要继续阅读下面的传统流程。看到每一步的“成功标志”后再进行下一步。

## 一、安装 Node.js

### Windows

1. 打开 [Node.js 官网](https://nodejs.org/)，下载 **LTS** 版本（推荐 Node.js 22）。
2. 双击安装包，一直点“Next”，保留默认选项，最后点“Install”。
3. 安装结束后，关闭并重新打开 Cursor。
4. 在 Cursor 顶部菜单点“终端 → 新建终端”，输入：

```bash
node -v
npm -v
```

成功标志：两条命令都显示版本号，例如 `v22.x.x` 和 `10.x.x`。

### macOS

1. 打开 [Node.js 官网](https://nodejs.org/)，下载 **LTS** 版本（推荐 Node.js 22）。
2. 双击 `.pkg` 文件，按提示完成安装。
3. 关闭并重新打开 Cursor。
4. 在 Cursor 顶部菜单点“终端 → 新建终端”，运行：

```bash
node -v
npm -v
```

成功标志：两条命令都显示版本号。若提示“command not found”，重启电脑后再试。

## 二、解压源码包

1. 找到卖家发送的压缩包。
2. Windows：右键压缩包 →“全部解压缩”；macOS：双击压缩包。
3. 将解压后的文件夹移到容易找到的位置，例如“文档/我的作品集”。
4. 打开该文件夹，确认能看到 `package.json`、`src`、`public` 和 `README.md`。

成功标志：`package.json` 与 `src` 文件夹在同一层。不要在压缩包预览窗口里直接运行项目。

## 三、用 AI 编程工具打开

### Cursor

1. 打开 Cursor。
2. 点“File（文件）→ Open Folder（打开文件夹）”。
3. 选择刚解压、里面有 `package.json` 的文件夹。
4. 若询问是否信任作者，确认来源是你的卖家后选择信任。

成功标志：左侧文件列表能看到 `src`、`public` 和 `package.json`。

### Codex、Claude Code 或同类工具

先用 Cursor/VS Code 打开项目文件夹，再打开内置终端。若工具需要从终端启动，先进入项目目录：

```bash
cd "你的项目完整路径"
```

然后按该工具官方说明启动。路径含空格或中文时必须保留双引号。把 [AI 提示词包](AI提示词包.md) 中的提示词发给工具，不要让 AI 自由重构项目。

成功标志：AI 明确说它已读取当前项目，并能找到 `src/content/siteConfig.ts`、`src/content/homeConfig.ts` 和 `src/content/showcases.ts`。

## 四、安装项目依赖

Windows 用户可直接双击项目根目录的 `open-dev.cmd`：它会自动完成首次安装并打开网站。若窗口出现红色错误，请不要关闭，先截图保存。

希望手动操作或使用 macOS 时，确认终端当前路径是项目文件夹，然后输入：

```bash
npm install
```

第一次可能需要几分钟。黄色警告通常不影响安装；不要因为看到 `warn` 就删除文件。

成功标志：命令结束后回到可输入状态，项目中出现 `node_modules` 文件夹，且最后没有红色的 `npm ERR!`。

## 五、在本机打开网站

输入：

```bash
npm run dev
```

终端会显示类似：

```text
Local: http://localhost:5173/
```

按住 `Ctrl`（macOS 可直接点击或按 `Command`）点击地址，也可以复制到浏览器。

成功标志：浏览器能看到作品集首页。此终端要保持运行；停止时按 `Ctrl + C`。

## 六、替换成你的内容

先备份整个项目文件夹，然后只处理以下位置：

1. 打开 `src/content/siteConfig.ts`，替换姓名、品牌、简介、邮箱和社交链接。
2. 打开 `src/content/homeConfig.ts`，替换首页文字、轮播和首页展示内容。
3. 打开 `src/content/showcases.ts`，替换作品分类、封面和详情媒体。
4. 将自己的图片、视频和 Logo 放入 `public/assets/`。
5. 配置中的素材路径以 `/assets/` 开头，例如 `/assets/my-cover.webp`。
6. 每改一小部分就保存，并回浏览器查看；开发服务器通常会自动刷新。

最稳妥的素材替换方式：使用相同格式和文件名覆盖示例素材。若修改文件名，也必须同步修改配置中的路径，并注意英文大小写完全一致。

成功标志：首页显示你的品牌和素材；点击每个作品都能打开，没有空白图片或播放失败图标。

不要让 AI 随意修改 `src/components/`、动画组件、页面路由或构建配置。普通换内容不需要重写这些文件。

## 七、运行交付检查

先在运行网站的终端按 `Ctrl + C`，再输入：

```bash
npm run template:check
```

成功标志：命令正常结束，没有 `error`、缺失素材或无效配置提示。若失败，把终端从命令开始到结尾的完整文字复制给 AI，并使用“排查报错”提示词。

然后测试正式构建：

```bash
npm run build
```

成功标志：出现构建成功信息，项目根目录生成 `dist` 文件夹。

> `npm run template:prepare` 是卖家整理交付包的命令。普通买家不要运行，除非卖家明确要求。

## 八、通过 GitHub 和 Vercel 上线

### 1. 上传到 GitHub

1. 注册并登录 [GitHub](https://github.com/)。
2. 安装并打开 [GitHub Desktop](https://desktop.github.com/)。
3. 登录 GitHub Desktop。
4. 选择“File → Add Local Repository”，选中项目文件夹。
5. 如果提示它不是仓库，点“create a repository”，仓库名可填 `my-portfolio`。
6. 左下角摘要填写 `更新个人作品集`，点击“Commit to main”。
7. 点击顶部“Publish repository”。
8. 建议勾选 **Keep this code private（保持私有）**，再确认发布。

成功标志：浏览器登录 GitHub 后能看到这个仓库和项目文件；仓库页面应保持 Private，避免公开交付源码。

### 2. 导入 Vercel

1. 打开 [Vercel](https://vercel.com/)，选择“Continue with GitHub”登录。
2. 允许 Vercel 访问刚才的仓库。
3. 点击“Add New → Project”，找到 `my-portfolio`，点击“Import”。
4. Framework Preset 应自动识别为 **Vite**。
5. Build Command 保持 `npm run build`，Output Directory 保持 `dist`。
6. 点击“Deploy”，等待部署完成。

成功标志：页面显示部署成功，并给出一个 `https://...vercel.app` 地址；打开后首页、作品详情、图片和视频都正常。

### 3. 以后更新网站

修改并检查完成后，在 GitHub Desktop 中填写更新说明，点击“Commit to main”，再点“Push origin”。Vercel 会自动重新部署。

成功标志：Vercel 项目中的最新 Deployment 显示 **Ready**，线上地址刷新后出现新内容。

## 上线前最后核对

- 手机和电脑都打开测试一次。
- 每个按钮、作品详情和外部链接都点一次。
- 邮箱、社交账号、姓名和版权年份正确。
- 没有示例人物、示例联系方式或不属于你的作品。
- `npm run template:check` 与 `npm run build` 均成功。
- GitHub 仓库保持私有，授权范围符合卖家提供的许可文本。
