# 常见问题

## 我完全不会编程，也能使用吗？

可以。先照着[零基础安装与上线](零基础安装与上线.md)完成本地预览，再只修改 `src/content/siteConfig.ts`、`src/content/homeConfig.ts`、`src/content/showcases.ts` 和 `public/assets/`。一次改一点，保存后立即查看效果。

## `node` 或 `npm` 不是内部命令 / command not found

Node.js 没装好，或安装后终端没有重启。安装 Node.js 22 LTS，完全关闭并重开 Cursor；仍无效时重启电脑，再运行：

```bash
node -v
npm -v
```

## `npm install` 很慢或失败

先确认网络正常，并等待几分钟。若最后出现 `npm ERR!`，复制完整报错给 AI，不要随意删除 `package-lock.json` 或更换依赖版本。公司网络、代理和安全软件也可能阻止下载。

## 出现很多黄色 `warn`，是不是坏了？

不一定。以命令最后结果为准：只要正常结束且没有 `npm ERR!`，通常可以继续。再运行 `npm run dev` 验证。

## `npm run dev` 提示找不到 `package.json`

终端开错文件夹了。先在左侧确认能看到 `package.json`，再从该项目打开新终端。不要在 `src`、`public` 或压缩包内部的错误层级运行命令。

## 端口 5173 被占用怎么办？

Vite 通常会自动使用 5174 等新端口。打开终端最新显示的 `Local:` 地址即可，不要固定只打开 5173。

## 浏览器打不开本地地址

确认 `npm run dev` 的终端仍在运行，并打开它当前显示的完整 `Local:` 地址。`localhost` 只能在运行项目的这台电脑上访问，不是线上网址。

## 修改后页面没变化

1. 确认文件已保存（`Ctrl + S`，macOS 为 `Command + S`）。
2. 确认改的是当前已打开项目里的配置文件。
3. 刷新浏览器；仍无变化时停止并重新运行 `npm run dev`。
4. 不要直接编辑 `dist`，它会在下次构建时被覆盖。

## 图片不显示或视频不播放

检查以下几点：

- 文件确实位于 `public/assets/` 内。
- 配置路径以 `/assets/` 开头，不要写 `public/assets/`。
- 文件名、扩展名和英文大小写完全一致；Vercel 对大小写更严格。
- 路径使用 `/`，不要使用 Windows 的 `\`。
- 浏览器常用图片格式为 WebP/JPG/PNG，视频优先 MP4（H.264）。

## 本地正常，Vercel 上素材却丢失

最常见原因是大小写不一致，或素材没有上传到 GitHub。打开 GitHub 仓库确认文件存在，再核对配置路径。修正后重新 Commit 和 Push，等待 Vercel 状态变为 Ready。

## 视频加载很慢

压缩视频并优先导出 MP4（H.264），首页移动端只保留 1～2 个较小素材。不要直接放数百 MB 的原始视频；大文件也可能超过 GitHub 或 Vercel 限制。

## 应该在哪里改姓名、联系方式和首页？

- 全站品牌与联系方式：`src/content/siteConfig.ts`
- 首页文字、轮播与展示内容：`src/content/homeConfig.ts`
- 作品分类、封面与详情：`src/content/showcases.ts`
- 图片、视频和 Logo：`public/assets/`

普通内容替换不要修改 `src/components/` 或动画组件。

## 可以让 AI 随便美化或重构吗？

不建议。AI 很可能改变动画、响应式布局或数据结构。使用[AI 提示词包](AI提示词包.md)，明确限制它只修改配置和素材引用。若确实要改组件，先单独备份，并一次只改一项。

## `npm run template:check` 失败怎么办？

阅读最后几行提示，通常是配置缺项、路径不存在、ID 重复或素材缺失。把完整输出发给 AI，并使用“排查报错”提示词。不要跳过检查直接上线。

## `npm run build` 失败怎么办？

先运行：

```bash
npm run template:check
```

若模板检查通过但构建仍失败，复制从执行 `npm run build` 开始到结束的全部终端文字给 AI。不要只发最后一行，也不要让 AI直接升级所有依赖。

## `template:prepare` 是做什么的？

它用于卖家整理、检查并准备干净的交付包。普通买家通常不需要运行 `npm run template:prepare`；除非卖家明确要求，否则只运行 `npm run template:check`。

## `dist` 文件夹是什么？

它是 `npm run build` 生成的成品文件夹。不要在里面改内容，也不用手工上传给采用 GitHub 集成的 Vercel；Vercel 会自动构建。

## GitHub 仓库应该公开吗？

建议保持 **Private（私有）**。购买使用权不等于可以公开模板源码。具体以卖家提供的授权条款为准。

## Vercel 部署失败或显示 Error

进入失败的 Deployment 查看日志，确认：

- Framework Preset 是 Vite。
- Build Command 是 `npm run build`。
- Output Directory 是 `dist`。
- GitHub 中已上传 `package.json`、`src`、`public` 和锁文件。

复制完整构建日志给 AI；日志里若包含密钥或隐私，先打码。

## 如何绑定自己的域名？

在 Vercel 项目中打开 “Settings → Domains”，输入已购买的域名，并按页面提示去域名服务商添加 DNS 记录。DNS 生效可能需要几分钟到 48 小时，以 Vercel 显示有效为成功标志。

## 网站上线后如何更新？

本地修改后依次运行 `npm run template:check` 和 `npm run build`。都成功后，通过 GitHub Desktop Commit 并 Push；Vercel 会自动发布新版本。

## 可以把这套源码卖给别人吗？

默认不可以。非独占商业使用通常允许用于自己的站点或客户项目，但不允许转售模板、公开源码或把源码当作自己的模板产品分发。最终范围以交易时双方确认的正式授权文本为准。
