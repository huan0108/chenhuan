# AI 提示词包

以下提示词可直接复制到 Cursor、Codex、Claude Code 或同类工具。首次启动使用第 0 条一口气完成；网站打开后，再按自己的实际需求选用其他提示词。执行内容修改前建议先备份项目。

## 必须放在每次对话开头的限制

```text
你正在协助一名完全零基础用户维护作品集模板。

硬性限制：
1. 只允许修改 src/content/siteConfig.ts、src/content/homeConfig.ts、src/content/showcases.ts，以及 public/assets/ 中素材的引用路径。
2. 除非我再次明确授权，不得修改 src/components、动画组件、路由、样式系统、构建配置、package.json 或依赖。
3. 禁止为了“优化”而重写动画组件、改变页面结构或删除现有效果。
4. 修改前先读取配置类型和现有写法；保持字段名、数据结构和 TypeScript 类型不变。
5. 素材文件只引用，不删除、不覆盖；如果找不到文件，先告诉我。
6. 每次只做我要求的内容。完成后列出修改文件，并运行 npm run template:check；不要运行 git、不要提交。
```

## 0. 让 Codex 接管首次安装

用户只需用 Codex 打开解压后的项目文件夹，然后复制下面整段：

```text
我是完全零基础用户。请先读取根目录的 AGENTS.md，并作为操作员连续完成这个作品集模板的首次本地启动。

请按顺序执行：
1. 确认当前目录同时存在 package.json、AGENTS.md、src 和 public；缺少任何一项就停止并告诉我选错了文件夹；
2. 检查 Node.js 和 npm 是否可用，Node.js 版本需不低于 20.19；
3. 如果缺少 Node.js，先说明需要安装的内容、来源和是否需要管理员权限，得到我确认后再安装；不能自动安装时给我官方下载入口；
4. 如果 Node.js 已符合要求，我授权你运行 npm install；若仅因全局 npm 缓存权限失败，可以改用当前项目内的 .npm-cache 安全重试，但不要删除 node_modules 或其他现有文件；
5. 运行 npm run template:check；
6. 运行 npm run dev，并告诉我浏览器应该打开的 Local 地址；
7. 看到网页后停止，不修改品牌、作品、动画、组件和依赖。

正常成功步骤之间不要反复询问我。只有涉及安装系统软件、管理员权限、删除或覆盖现有文件、登录、上传、创建仓库或发布时才暂停确认。遇到报错先解释，不要使用强制升级、强制删除或跳过检查。
```

成功后，用户不需要自己输入 `npm install` 或 `npm run dev`。

网站打开后无需填写固定问卷。直接用自然语言告诉 AI 想替换、增加、删除或调整什么；AI 只应在完成当前需求确实缺少信息时集中提问。

## 1. 初始化：理解项目

```text
[先粘贴上面的硬性限制]

请先只读检查当前项目，不要修改文件。用零基础用户能懂的话告诉我：
1. src/content/siteConfig.ts 中哪些字段控制品牌、个人简介、联系方式和社交链接；
2. src/content/homeConfig.ts 中哪些字段控制首页文字和首页轮播；
3. src/content/showcases.ts 中哪些字段控制作品分类、封面和详情；
4. public/assets 中素材应该怎样放置和引用；
5. 我需要提前准备哪些文字、图片和视频。
最后给我一份简短替换清单。不要分析或改写动画组件。
```

## 2. 替换品牌信息

先把方括号内容换成你自己的信息：

```text
[先粘贴上面的硬性限制]

请只修改 src/content/siteConfig.ts，把品牌信息替换为：
- 显示名称：[你的姓名或品牌名]
- 一句话介绍：[你的职业和方向]
- 详细简介：[你的简介]
- 邮箱：[你的邮箱]
- 微信/电话：[不公开可写“留空”]
- 小红书：[链接或留空]
- Behance：[链接或留空]
- 其他社交链接：[链接或留空]

保留原有字段和数据结构。空信息使用项目现有允许的空值写法，不要编造内容。完成后运行 npm run template:check。
```

## 3. 替换首页轮播

先把素材复制到 `public/assets/`，再使用此提示词：

```text
[先粘贴上面的硬性限制]

请只修改 src/content/homeConfig.ts 中的首页轮播配置，不要修改轮播或动画组件。

桌面端按以下顺序显示：
1. [例如 /assets/hero/01.webp，图片，说明文字]
2. [例如 /assets/hero/02.mp4，视频，说明文字]

移动端按以下顺序显示：
1. [建议只填 1～2 个较小素材]

请先确认这些文件在 public/assets 中真实存在，再按当前配置类型填写。图片和视频类型必须正确，不存在的路径不要写入。完成后运行 npm run template:check。
```

## 4. 更新作品

每次只新增或修改少量作品：

```text
[先粘贴上面的硬性限制]

请只在 src/content/showcases.ts 的现有作品配置中[新增/修改/删除]以下作品，不要改页面组件：
- 所属分类：[分类名称]
- 作品 ID：[唯一英文短名，例如 brand-redesign]
- 标题：[作品标题]
- 简介：[1～2 句话]
- 封面：[例如 /assets/works/brand-redesign/cover.webp]
- 详情素材（按顺序）：
  1. [素材路径]
  2. [素材路径]

先确认素材文件存在，检查 ID 不重复，并完全沿用现有对象结构。不要移动或删除其他作品。完成后运行 npm run template:check。
```

## 5. 排查报错

```text
[先粘贴上面的硬性限制]

我执行命令时遇到以下报错：

[粘贴：执行的命令、从报错开始到结束的完整终端文字]

请先诊断，不要直接大改。按以下顺序处理：
1. 用一句话说明最可能原因；
2. 检查 Node/npm 版本、当前目录、依赖安装、配置格式和素材路径；
3. 如果只需修改 src/content/siteConfig.ts、src/content/homeConfig.ts、src/content/showcases.ts 或素材引用，请做最小修改；
4. 如果必须修改组件、动画、路由、package.json、依赖或构建配置，请停止，只告诉我原因和建议改动，等我授权。

修复后运行原失败命令和 npm run template:check。不要运行 git。
```

## 6. 上线前检查

```text
[先粘贴上面的硬性限制]

请对当前作品集做上线前只读检查：
1. 运行 npm run template:check；
2. 运行 npm run build；
3. 检查三个内容配置文件中是否仍有示例姓名、示例联系方式、占位文字、空链接和重复作品 ID；
4. 检查所有已引用的 public/assets 素材是否存在，注意文件名大小写；
5. 检查是否有不应公开的密钥、密码或个人隐私；
6. 给我一份“必须修复”和“建议优化”清单。

先不要修改任何文件。不要改动画组件，也不要运行 git。若检查通过，明确告诉我可以进入 Vercel 部署步骤。
```

## 7. 让 Codex 协助上线

这段提示词可以完成技术操作，但 GitHub/Vercel 登录、验证码、授权页面和最终发布确认仍由用户亲自完成。它是上线专用提示词，不要同时粘贴前面“不要运行 Git”的限制：

```text
请协助我把当前作品集上线，但任何外部发布操作都必须先征得我的确认。

按顺序进行：
1. 运行 npm run template:check、npm run lint 和 npm run build；
2. 检查项目中没有 .env.local、密钥、密码或不应公开的信息；
3. 检查 Git 是否可用；如未初始化，先告诉我将创建哪些文件，再等我确认；
4. 检查 GitHub CLI 或其他可用的安全上传方式；
5. 仓库必须设为 Private，创建仓库、提交和推送前分别让我确认；
6. 协助连接 Vercel。遇到浏览器登录、验证码或授权页面时暂停，让我亲自完成；
7. 部署完成后检查线上首页和作品详情，并把最终网址发给我。

不得公开仓库，不得输出、记录或上传任何密钥，不得使用强制推送。
```

## 使用诀窍

- AI 说要“大规模重构”时先拒绝；换品牌和作品不需要重构。
- 一次替换 1～5 个作品，出错更容易定位。
- 不要只发截图；终端报错应复制为文字，并包含你执行的命令。
- AI 修改后先看文件差异，再运行检查和本地预览。
